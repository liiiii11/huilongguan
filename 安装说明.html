一、概述与功能介绍

本工具是一个多用户销售业绩记录系统，基于 Supabase 云端数据库，支持：

• 多账号协作（店长 + 员工，1~5人）
• 业绩过渡审批功能（过渡者发起，被过渡人审批）
• 云端数据实时同步
• 月度总结与数据导出（CSV）
• 日历视图展示每日收益
• 提成类型管理（主分类 + 子分类）
• 业绩图片附件（每条最多3张）

技术栈：纯前端 HTML + JavaScript + Supabase（PostgreSQL），无需服务器，部署到 Netlify 即可使用。

二、文件清单

解压 sales-tracker-完整版.zip 后，文件结构如下：

sales-tracker/ ├── index.html ← 网站首页（Netlify 入口文件） ├── sales-tracker.html ← 同 index.html（备用） ├── _headers ← Netlify 缓存配置 ├── schema.sql ← 数据库初始化脚本（首次安装必须运行） ├── update-v2.sql ← 更新脚本 v2（员工权限） ├── update-v3.sql ← 更新脚本 v3（过渡人字段） ├── update-v4.sql ← 更新脚本 v4（过渡审批功能） ├── 安装说明.html ← 本文档 ├── 使用说明.html ← 使用手册 ├── 部署指南.html ← 图文部署指南 ├── _shared/ │ ├── fonts/ ← 字体文件 │ └── js/ │ └── echarts.min.js ← 图表库 └── assets/ ├── config.js ← Supabase 配置文件（需要修改！） ├── data-layer.js ← 数据层逻辑 ├── app.js ← 应用主逻辑 ├── supabase-client.js ← Supabase 客户端 └── supabase-js.min.js ← Supabase SDK
重要：首次安装时，schema.sql 和 update-v4.sql 必须运行，其余更新脚本可跳过（新项目已包含全部字段）。

三、注册 Supabase 并创建项目

1
注册账号

打开 https://supabase.com，点击右上角 Start your project，用 GitHub 账号或邮箱注册。

2
创建新项目

登录后点击 New Project，填写：

• Name：sales-tracker（可自定义）
• Database Password：设置密码并记录下来
• Region：选择 Southeast Asia (Singapore) 或最近的区域

3
等待初始化

点击 Create new project，等待 1-2 分钟项目初始化完成。

4
获取 API 配置信息

进入项目后，点击左侧栏 Settings（齿轮图标）→ API，复制以下两个值：

• Project URL：形如 https://xxxxx.supabase.co
• anon public key：一长串字母数字

四、初始化数据库

1
打开 SQL Editor

在 Supabase Dashboard 左侧栏点击 SQL Editor，点击 New query。

2
运行 schema.sql

打开本工具的 schema.sql 文件，复制全部内容粘贴到编辑器，点击 Run。

看到绿色成功提示后，说明数据库表已创建完成。

3
运行 update-v4.sql

再点 New query，打开 update-v4.sql 文件，复制全部内容粘贴运行。

这一步添加过渡审批功能所需的 transfer_status 字段。

提示：如果你是新项目且 schema.sql 中已包含 transfer_status 字段，则 update-v4.sql 可以跳过。但运行也不会报错，建议运行以确保完整。

五、修改代码配置

用记事本或代码编辑器打开 assets/config.js 文件，将内容替换为你的新项目信息：

var SUPABASE_CONFIG = {
  url: 'https://你的项目地址.supabase.co',
  anonKey: '你的anon_public_key'
};

function isSupabaseConfigured() {
  return SUPABASE_CONFIG.url && SUPABASE_CONFIG.anonKey &&
    SUPABASE_CONFIG.url.indexOf('supabase.co') >= 0;
}
注意：anon key 是公开密钥，配合 RLS 策略使用是安全的。但绝不要在这里放入 service_role key！

修改完成后保存文件。

六、配置邮箱登录

1
确认 Email 登录已启用

点击左侧栏 Authentication → Providers，确认 Email 已启用（默认启用）。

2
关闭邮箱验证（推荐）

在 Authentication → Settings 中，关闭 "Confirm email"。这样注册后无需邮箱验证即可直接登录，方便快捷。

七、部署到 GitHub + Netlify

7.1 上传到 GitHub

1
创建仓库

打开 https://github.com 登录，点击右上角 + → New repository。

填写 Repository name：sales-tracker，选择 Private（推荐私有），点击 Create repository。

2
上传文件

在仓库页面点击 uploading an existing file，把 sales-tracker 文件夹里的所有文件和文件夹拖进去。

点击 Commit changes 提交。

7.2 用 Netlify 部署

1
登录 Netlify

打开 https://app.netlify.com，用 GitHub 账号登录。

2
导入项目

点击 Add new site → Import an existing project，选择 GitHub，找到 sales-tracker 仓库。

3
配置部署

设置如下：

• Build command：留空（不填）
• Publish directory：.（一个点，表示根目录）

4
部署完成

点击 Deploy site，等待 1-2 分钟。部署成功后会得到一个网址，如 https://xxx-xxx-xxx.netlify.app。

完成！现在可以打开这个网址开始使用了。

八、首次使用

1
注册账号

打开部署后的网址，点击 注册，填写昵称、邮箱、密码。

2
创建店铺

首次注册会进入 店铺设置 页面，选择 创建店铺，填写店铺名称。第一个注册的人自动成为店长。

3
获取邀请码

创建成功后会显示 邀请码（6位字母数字）。把邀请码分享给同事，他们注册后选择 加入店铺 即可。

4
设置提成类型

进入 设置 → 提成类型管理，添加你的提成主分类和子分类（如：主机类/PS5、提成比例5%等）。

九、后续更新代码

以后需要更新代码时：

1
修改本地文件

在本地修改代码文件。

2
上传到 GitHub

十、常见问题

Q: 注册后看不到登录页面？
检查 config.js 中的 URL 和 Key 是否正确填写。URL 必须以 https:// 开头，以 .supabase.co 结尾。
Q: 提示 "Supabase SDK 加载失败"？
可能是网络问题，刷新页面重试。确保 assets/supabase-js.min.js 文件存在且未损坏。
Q: 数据库报错 "relation does not exist"？
说明 schema.sql 没有运行成功。重新在 SQL Editor 中粘贴运行，注意看是否有红色错误提示。
Q: 过渡审批功能不生效？
确认已在 Supabase 中运行了 update-v4.sql，添加了 transfer_status 字段和对应的 RLS 策略。
Q: Netlify 部署后显示 "Page not found"？
确保 Publish directory 设置为 .（根目录），且仓库中有 index.html 文件。
Q: 注册时提示 "User already registered"？
说明该邮箱已注册过，直接用该邮箱登录即可。
Q: 数据可以导出吗？
可以。在月度总结页面点击导出按钮，可将当月数据导出为 CSV 文件。
